# Коротка синхронізація іспиту — Літакова 1.2.57 / 181

Клієнт запитує короткі відповіді лише для проміжного збереження або читання
вже відомої активної спроби. Сервер перевіряє поточний акаунт, ID тесту й
спроби, версію документа, ПК-власника, fence та стан спроби. Для запису
також звіряються підтверджений ID запиту, ПК і очікувана нова ревізія.
Незмінені читання не розбирають повторно питання й не переписують повний
локальний профіль. Збереження не розбирає набір питань удруге лише для відповіді.

Початок, передача, захоплення й завершення спроби повертають повні дані.
Зміна власника, ревізії, спроби або стану також переводить читання на повну
відповідь. Підтвердження короткого формату прив'язане до локального набору
питань цієї ж спроби, незмінних часу початку й дедлайну. Збереження відповіді
на сервері залишається підтвердженим перед ACK. Формат збережених документів,
питання спроби та схема таблиць не змінені.

Невідповідне коротке підтвердження запускає один повтор без короткого формату;
ID запиту та контрольна копія відповідей зберігаються. Неочікувана коротка
відповідь після цього відхиляється. При зміні акаунта повтор з попереднім
сеансом не виконується. Новий клієнт приймає повні відповіді старого сервера;
старі клієнти не запитують короткий формат і продовжують отримувати повні дані.

## Відтворюване порівняння

Ті самі синтетичні питання та серверна модель; порівняно попередні функції
1.2.56 з новими. У копії попереднього сервера змінено лише рекламовані номер
і назву версії для контракту тестового стенда. Показані байти UTF-8 JSON
після розпакування, а не обсяг TCP-трафіку чи виграш часу відповіді.

Після заповнення відповідей коротке читання містить також їхній компактний

тесту. Скорочення JSON не є твердженням про пропорційне прискорення Google.

## Перевірки

Пройдено 24 цільові сценарії зі справжніми обробниками й контролером:
50 питань з вибором, 200 змішаних питань, сумісність обох напрямків,
пошкоджені й непрохані короткі відповіді, повтор без дубля, втрата ACK,
новий текст під час запиту, передача між ПК, завершення з іншого процесу,
зміна акаунта, відкликання доступу, сталість часу й дедлайн.
Підказка чужої спроби не повертає чужі дані. Короткий протокол не обходить
вимогу сумісності питань із кількома правильними варіантами.

Пройдено локальні перевірки моделей та UI. Окремо пройдено 22 перевірки
продовження іспиту та 8 перевірок повтору неповної відповіді сервера.

коротким підтвердженням. Фінальний контроль GitHub 46138515948 пройдено на коміті
`e2bff09916d0c8735afe15a433937401b022b1f1`; його архів звірено за SHA-256
`5a0ca9226fb64e102f8ab74b3e1e5a02ff9e21c665ea02185db4f75dbdb2a986`.
Звіти підтверджують 24 перевірки протоколу та 29 сценаріїв / 108 натискань;
SHA-256 сервера й контролера відповідають остаточним джерелам.

до будь-якого надсилання в хмару. Обидві відмови відтворено в тестах.
Сервер і формат обміну після запуску живого контролю не змінювалися.

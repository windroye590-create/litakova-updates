# Розширена перевірка Літакової 1.2.52 / 176

Перевірено поточний код, повторно завантажений опублікований EXE,
серверний API та сценарії роботи з відмовами. Перевірка доповнює
[попередній аудит і три виправлення](2026-11-25-review.md).
Навчальні акаунти, відповіді та результати не змінювалися. FPV не змінювався.

Повний прогін завершився успішно. Нових відтворюваних помилок застосунку
в перевірених сценаріях не виявлено; поточним випуском залишається 1.2.52.

## Опублікований застосунок і сервер

- Стабільний випуск: `v1.2.52`, код `176`.
- Повторно завантажені чотири файли випуску збігаються з `channel`.
  Підпис каталогу дійсний; усі 27 ресурсів EXE відповідають поточному коду.
- Із ресурсів саме цього EXE пройдено 11 сценаріїв запуску, відновлення
  офлайн-сесії, читання журналу й обробки відсутнього модуля.
- SHA-256 EXE: `7a0aca189ff7cfdd56e8ec7001858c1b7d21e741cd70b4c2b9c2ff4e5ec5453e`.
- Один запит здоров'я живого сервера підтвердив API 26,
  `pc-api26-5798277cf35550b9` і можливості редагування ПІБ/відповідей.
  Цей запит не змінював навчальних даних.
- Для цього самого випуску збережені успішні звіти реального Windows:
  16 перевірок DPAPI/CNG/сховища та 5 перевірок WinHTTP/gzip.
  Нативний код у межах цього аудиту не змінювався.
- Для включеного в EXE jsPDF 4.2.1 реєстр npm не повернув повідомлень
  про вразливості. Це вузька перевірка відомих повідомлень для однієї бібліотеки.
  Звичайний `npm audit` без lock-файлу тут непридатний; lock-файл не створювався.

## Межі висновків

Синтетичні 120 клієнтів не вимірюють пропускну здатність живого Google Apps
Script. Прискорений час моделі й затримки на тестовій машині не є прогнозом
часу здачі на навчальних ПК. Браузерний тест використовує окремий стан
кожного клієнта; реальну криптографію Windows перевіряє окремий нативний набір.

Повне оновлення даних вручну та холодний запуск після втрати кешу досі
можуть створювати навантаження. Обмеження Google, мережі й повільні операції
таблиць можуть давати затримки, навіть коли повторне надсилання працює
правильно. Масове оновлення чи здача на живому сервері в цьому аудиті
навмисно не запускалися.

Зміни цього аудиту стосуються тестів і документації. Версія застосунку,
сервер, навчальні дані та FPV через цей аудит не оновлювалися.

Для повторення потрібні Node.js, Python, GCC/OpenSSL, встановлені
залежності тестування і Chromium. З каталогу `source`:

```sh
npm run test:global-audit
python3 -m unittest discover -s ../release-tools/tests -p 'test_*.py'
PACKED_EXE=/path/to/published/Litakova-Komisiia-PC.exe node tests/packaged-startup.mjs
```

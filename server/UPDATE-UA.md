# Оновлення сервера до API 17

Версія ПК 1.2.12 / 135 працює з чинними короткими тестами на попередньому
сервері. Для збереження великих тестів потрібне одноразове оновлення сервера.
Саме оновлення EXE не змінює розгортання Google Apps Script.

1. Відкрийте чинний проєкт Google Apps Script цієї комісії.
2. Замініть вміст Code.gs файлом Code.gs з цього комплекту та збережіть проєкт.
   Збережіть чинне значення SPREADSHEET_ID, якщо цей код використовується для
   іншої комісії. Не створюйте нову базу або нове розгортання.
3. У «Розгорнути» → «Керувати розгортаннями» відредагуйте чинний вебзастосунок,
   виберіть нову версію та розгорніть її зі збереженням наявної адреси /exec.

Після першого API-запиту сервер сам додасть прихований аркуш _Частини_тестів.
Старі питання, групи, облікові записи, результати та письмові перевірки не
потребують перенесення. Старі короткі тести продовжують читатися у своєму форматі.

Контроль: відповідь GET за чинною адресою /exec повинна містити version: 17,
serverBuild: pc-1.2.12-large-tests і chunkedTests: true. У застосунку натисніть
«Оновити», щоб отримати нові можливості сервера.

Новий формат пише частини питаннями/даними у безпечні клітинки й публікує
посилання лише після успішної перевірки всіх частин. Якщо частина втрачена чи
пошкоджена, робота не оцінюється як порожній тест. Зворотне розгортання старого
Code.gs після створення великих тестів не підтримує новий формат: залишайте API 17
або новішу сумісну версію. Резервну копію бази можна зберігати звичним способом.

Межа кількості залишається 200 питань. Межі тексту окремого питання, варіанта
відповіді й сумарного обсягу письмових відповідей не змінювалися.

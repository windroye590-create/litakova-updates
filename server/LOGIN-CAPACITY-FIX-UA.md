# Виправлення глобального блокування входу — API 20

3 листопада 2026 року. Серверна збірка `pc-1.2.16-login-capacity`.

## Що виправлено

Раніше 1000 різних неправильних логінів заповнювали сховище лічильників і
змушували сервер повертати `LOGIN_THROTTLED` для всіх нових імен, включно з
правильним входом курсанта або інструктора. Збій відтворено через чинні
`/api/challenge` та `/api/login` на ізольованій моделі до внесення правки.

Тепер перед створенням нового лічильника сервер видаляє прострочені й
нечитабельні записи, а при заповненні — найстаріші за початком їхнього
п'ятихвилинного вікна. Звільняється рівно стільки місця, щоб після запису
залишилося не більше 1000 лічильників. Сортування не залежить від порядку
властивостей. Операція виконується під тим самим серверним блокуванням.

Існуючий лічильник оновлюється без витіснення інших. Хвилинне обмеження
конкретного логіна після восьми невдалих спроб збережено. Це виправлення
пункту 1; механіку відновлення іспитів і пункт 2 не змінено.

## Перевірки

- Новий `tests/login-capacity.mjs`: 12 сценаріїв. До правки падає на
  переповненні; після правки проходить.
- 1000 різних неправильних входів через API, потім новий неправильний вхід
  і правильні входи курсанта та інструктора при заповненому сховищі.
- Ще 1500 неправильних входів із повторними правильними входами під час
  заповнення; місткість не перевищується.
- Зворотний порядок властивостей, початково 1005 записів, прострочення,
  нечитабельний запис, восьма помилка, зникнення кешу, завершення паузи,
  зайняте блокування, помилка видалення та одноразовість challenge.
- Таблиці користувачів, результатів та всі сторонні властивості після
  перевірок збігаються з початковими.
- Повний `npm test`, включно з новим набором, пройдено.

Використовувалися тільки синтетичні дані й реальні серверні функції з
локальною моделлю Google. Запити навантаження до робочого сервера не
надсилалися. Реальні квоти Google цими перевірками не вимірюються.

## Активація

Правку активовано 3 листопада 2026 року: чинне розгортання оновлено
з версії 29 до версії 30. Адреса вебдодатка, виконання від імені власника
та чинний доступ збережені. Відповідь робочого API підтвердила нову збірку
`pc-1.2.16-login-capacity` і стан `online`.

Перед збереженням чинний код із редактора звірено за SHA-256 з вихідною
версією. Вставлений код збігається з перевіреним `Code-API20.gs`:
`5ad25e5fdf8f7d535c08e59dbbb900de4cabe1f9da636aae582913990eecc387`.
`setupCommission()` не запускали, таблиці не мігрували й дані не очищували.

Публічний `doGet` після активації повернув `version: 20`,
`serverBuild: pc-1.2.16-login-capacity`, `status: online`.

Оновлювати або перебудовувати Windows EXE для цієї серверної правки не
потрібно. Чинний EXE 1.2.16 та підписаний канал автооновлення не змінювалися.

## 1.2.49

Оптимізовано передачу великих тестів і час загального блокування записів.

Windows-модуль тепер приймає стиснені gzip/deflate відповіді Google та прозоро розпаковує їх перед передаванням застосунку. На системах, де цей режим недоступний, залишається звичайна передача. Обмеження розміру перевіряється після розпакування.

Для сучасного протоколу проходження запис відповідей і ревізій завершується до зняття блокування. Копіювання великої публічної спроби, формування розбору результату та серіалізація JSON виконуються після цього, щоб інші ПК раніше могли зберегти свою роботу. Старі клієнти зберігають сумісність.

Збій підтвердження запису не показує успіху й залишає обов'язок відновлення. Повторне завершення після втрати відповіді повертає той самий результат. Перевірено 200 питань, повний набір відповідей, приватність ключів відповідей, пошкоджені й завеликі стиснені відповіді.

Реальний Google-сервер підтвердив gzip на окремому запиті перевірки стану без входу до навчальних акаунтів. Навантаження живого класу та його час проходження не вимірювалися.

## 1.2.39

У редакторі тестів під полями «Зразок відповіді / критерії для викладача» та «Пояснення після тесту» додано короткі підказки й приклади.

Пояснено ручне оцінювання за змістом відповіді та різницю між приватними критеріями викладача й поясненням для курсанта. Підказки видно і після заповнення полів.

## 1.2.38

Модуль створення PDF підключається лише під час першого експорту відомості. Під час запуску застосунок більше не завантажує й не виконує цю бібліотеку.

Після першого експорту модуль використовується повторно. Одночасні запити ділять одне завантаження; після помилки або зависання можна повторити експорт без перезапуску. Бібліотека й шрифт залишаються всередині EXE.

# Версія 1.2.36

Літакова Комісія — видалення акаунтів зі старими результатами без ID.

- Перед видаленням курсанта застосунок показує старі рядки, належність яких сервер не може визначити однозначно. Для кожного рядка потрібно вибрати: видалити разом із цим акаунтом або залишити для іншої людини.
- Вибір діє лише для цього курсанта, інструктора й незміненого рядка. Зміна даних або завершення строку підтвердження потребує нового перегляду.
- Рядки з ID іншого курсанта та записи, обрані для збереження, залишаються в таблиці. Суперечливі ID продовжують блокувати видалення.
- Після видалення останнього курсанта можна видалити порожню групу, якщо вона не призначена тестам.

Потрібен чинний сервер API 26 із цим виправленням; процес випуску оновлює його перед публікацією EXE. Додано серверні та браузерні регресії для старих рядків, тезок, зміни даних після перегляду й видалення групи.

# Версія 1.2.35

Локальний модуль залишається доступним, коли браузер призупиняє фонове вікно. Закриття вікна передається окремим запитом; оновлення сторінки має час для повторного підключення. Під навантаженням модуль повертає повідомлення «зайнятий» замість обриву з’єднання. Помилка втрати зв’язку показує інструкцію українською.

# Літакова Комісія для Windows 1.2.31 / 155

Об’єднано верхні кнопки «Синхронізувати» та «Оновити» в одну — **«Оновити дані»**.

Кнопка спочатку зберігає локальні зміни, надсилає результати й прогрес матеріалів,
оновлює дані відкритого розділу та синхронізує чернетки акаунта. Картка курсанта,
матеріали, черга перевірки, банк питань та аналітика оновлюються через той самий процес.

Повторні натискання приєднуються до поточного циклу. Зайву повторну синхронізацію
акаунта всередині ручного оновлення прибрано. Фонові операції чекають завершення
цього циклу; збереження активного іспиту й утримання перевірки продовжують працювати.

Помилки запису, невідправлені результати й конфлікти чернеток відображаються
окремо та зберігають свої дії відновлення. Перемикання акаунта припиняє решту
операцій попереднього користувача.

Стабільний випуск **1.2.31 / 155**, сумісний із чинним Apps Script API 26.
